# ماندگاری نشست ورود

## رفتار پیاده‌سازی‌شده

پس از ورود موفق با رمز یا OTP:

```text
Supabase Auth → ذخیره خودکار session و refresh token در storage داخلی
AuthUserCache → ذخیره فقط id، نام، ایمیل، نقش و avatar (بدون token)
```

در شروع سرد برنامه:

```text
نمایش «در حال بازیابی نشست ورود»
→ awaitInitialization پلاگین Auth
→ خواندن session ذخیره‌شده
→ refreshCurrentSession برای تعویض access token منقضی
→ تطبیق id پروفایل cached با id نشست
→ تلاش حداکثر ۵ ثانیه برای تازه‌سازی profiles
→ استفاده از cache هم‌هویت در نبود اینترنت
→ ورود مستقیم به داشبورد بدون نمایش لحظه‌ای فرم ورود
```

اگر بازیابی به‌علت خطای موقت شکست بخورد، برنامه فرم ورود را به‌اشتباه نمایش نمی‌دهد و صفحه «تلاش دوباره» نشان می‌دهد.

## جداسازی بررسی بروزرسانی از نشست کاربر

جدول `app_version` عمومی و فقط‌خواندنی است. بررسی نسخه با `PublicUpdateSupabaseProvider` انجام می‌شود که فقط Postgrest دارد و Auth روی آن نصب نیست. در نتیجه access token منقضی کاربر به درخواست نسخه تزریق نمی‌شود و خطای `JWT expired` مانع دانلود بروزرسانی نخواهد شد.

## مواردی که نشست را حفظ می‌کنند

- بستن و بازکردن برنامه
- Force stop و اجرای دوباره
- کشته‌شدن process توسط Android
- بروزرسانی درجا با همان `applicationId` و همان امضا
- منقضی‌شدن access token، تا وقتی refresh token معتبر باشد
- قطع موقت اینترنت، اگر پروفایل همان کاربر قبلاً cache شده باشد

## مواردی که طبیعتاً نیازمند ورود دوباره‌اند

- حذف کامل برنامه
- پاک‌کردن App data از تنظیمات Android
- لغو نشست یا refresh token در Supabase
- تغییر package یا امضای APK
- مهاجرت از Debug با `ir.exam.app.native` به Release با `ir.exam.app`؛ این دو برنامه storage جدا دارند
- اولین جایگزینی WebView با Native، اگر نشست قدیمی فقط داخل WebView localStorage بوده باشد

پس از اولین ورود در نسخه Native Release، بروزرسانی‌های بعدی Release نشست را حفظ می‌کنند.

## اصول امنیتی

- access token و refresh token در `AuthUserCache` نوشته نمی‌شوند.
- cache فقط اطلاعات نمایشی پروفایل را نگه می‌دارد.
- cache فقط وقتی استفاده می‌شود که `userId` آن دقیقاً با userId نشست Supabase یکی باشد.
- نبود session معتبر باعث پاک‌شدن cache قدیمی می‌شود.
- خطای شبکه با «نبود پروفایل» اشتباه گرفته نمی‌شود و پروفایل student ناخواسته ساخته نمی‌شود.

**برای پشتیبانی:** در سایت، `localStorage.getItem('examsite.session.diag.v1')` ده رویداد آخر را نشان می‌دهد
(`refresh-ok` / `refresh-network` / `refresh-invalid-400` / `adopt-other-tab` / `storage-sync` / `user-logout`).
در اپ، `adb logcat -s SessionDiag` دلیل خواندن نشست را نشان می‌دهد.

**نکتهٔ باقی‌مانده:** اگر APK با کلید امضای دیگری نصب شود، Android اجازهٔ «آپدیت» نمی‌دهد و کاربر ناچار به حذف/نصب دوباره می‌شود؛ در آن حالت همهٔ دادهٔ برنامه (از جمله نشست) از بین می‌رود و هیچ کدی نمی‌تواند آن را برگرداند. امضا باید ثابت بماند (`release.keystore` یکسان در Secrets).
